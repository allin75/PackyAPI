# 排行榜整点与部分失败刷新设计

## 目标

排行榜改为每小时整点过期，并由整点后的第一个访问请求触发刷新。刷新某个账号失败时，继续刷新其他账号；失败账号沿用上次成功用量并显示“沿用上轮”。服务端不运行后台定时任务。

## 已确认行为

- 排行榜周期按自然小时计算，例如 `09:00` 到 `10:00`。
- 整点时无人访问则不发起请求；整点后的第一个排行榜请求触发整轮刷新。
- 同一轮的并发请求继续复用一个刷新任务。
- 账号按顺序逐个访问 Packy，避免并发请求上游。
- 单个账号失败不会终止整轮刷新。
- 失败账号有历史快照时沿用上次成功用量，并标记为“沿用上轮”。
- 新加入账号首次刷新失败时保留在榜单中，用量显示“暂不可用”并标记为“沿用上轮”。
- 所有账号按本轮可用值统一排序；失败账号使用旧用量参与排序，名次可以变化。
- “我的用量”保持请求驱动：仅在页面打开、页面倒计时触发或手动刷新时请求。页面关闭后服务端不刷新，并继续使用现有 5 分钟账号缓存。

## 调度设计

新增纯函数计算下一整点：

```text
nextHour = (floor(now / 3600) + 1) * 3600
```

排行榜快照的 `next_refresh_at` 保存下一整点，而不是“本次刷新时间 + 5 分钟”。服务启动后不创建定时器；`GET /api/leaderboard` 发现 `next_refresh_at <= now` 时才触发刷新。

首次没有快照时，第一个请求立即生成快照，并把下一次刷新时间设为下一整点。加入或移出排行榜仍会立即使快照过期；随后第一个请求立即刷新，完成后重新对齐下一整点。

## 部分失败处理

刷新开始时按 `account_id` 建立上一轮快照索引，然后遍历全部参榜账号：

1. 请求成功：使用最新名称和用量，行的 `observed_at` 设为本轮生成时间。
2. 请求失败且有历史行：沿用历史名称、用量和原 `observed_at`。
3. 请求失败且无历史行：使用账号名称、空用量，并把 `observed_at` 设为 `0`。
4. 不再因失败执行 `break`，继续处理后续账号。

现有 `leaderboard_snapshots.observed_at` 可以表达数据新旧，无需数据库迁移。返回排行榜时，行的 `observed_at < generated_at` 即表示 `stale: true`。旧数据库中的有效行原本就有 `observed_at == generated_at`，因此兼容现有数据。

整轮结束后，无论成功账号数量多少，都保存一份新快照，并把下一次刷新时间设为下一整点。旧的全榜 10 分钟退避状态和笼统的“上游限流”提示将移除。

## 排名与接口

成功账号使用新用量，失败账号使用旧用量，首次失败账号使用空用量；统一按现有规则排序。名次变化仍相对上一轮名次计算。

排行榜公开账号对象增加：

```json
{
  "stale": true
}
```

该字段不包含账号 ID、Key、IP 或剩余额度。顶层快照继续返回 `generatedAt` 和 `nextRefreshAt`。

## 页面表现

- 标题区域改为“整点刷新 · 较上轮排名”。
- 倒计时完全使用服务端 `nextRefreshAt`，显示距离下一整点的时间。
- `stale: true` 的账号在名称附近显示“沿用上轮”小标记。
- 空用量继续显示“暂不可用”。
- 部分失败不显示整页错误横幅，其他账号和新快照照常展示。

## 测试

新增或调整测试覆盖：

- 首次访问立即刷新，下一次时间对齐整点。
- 整点前重复访问不刷新，整点后首次访问刷新。
- 整点后的并发请求合并为同一轮。
- 中间账号失败后仍继续刷新后续账号。
- 失败账号沿用旧用量、标记为旧数据并参与重新排序。
- 新账号首次失败时显示空用量和旧数据标记。
- 全部账号失败时仍生成新快照，并对齐下一个整点。
- 加入或移出排行榜后保持即时刷新。
- “我的用量”继续使用 5 分钟请求缓存，不引入后台任务。
- 页面显示“整点刷新”和“沿用上轮”。

## 部署与兼容性

不修改数据库 schema，不修改 Cookie、会话或 Cloudflare 配置。Compose 中的 `REFRESH_INTERVAL_SECONDS=300` 继续只控制账号用量缓存。部署前保留现有 `data/` 和 `secrets/`，重建 `packy-usage` 容器后验证公网排行榜的下一次刷新时间落在自然整点。
