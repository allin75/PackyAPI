# 每账号周用量曲线设计

## 目标

在 `/my` 的每个账号卡片内增加独立的周用量曲线。默认显示当前周周一至周日，用户可以用左右箭头快速翻周，也可以点击日期区域选择任意日期并跳到该日期所在周。页面只读取现有每日快照，不增加后台查询、不修改数据库结构。

## 已确认行为

- 每个账号卡片默认展开一张自己的周曲线，各账号可以停留在不同周。
- 一周固定为周一至周日，数据库 `usage_date` 直接作为页面显示日期。
- 日期选择器是一个三行整体：第一行显示月份，第二行显示七个日号，第三行显示 `一 二 三 四 五 六 日`。
- 跨月周的月份显示为 `8月 / 9月`；同月只显示一个月份。
- 左箭头切到上一周，内容从左侧进入并向右滑动；右箭头切到下一周，内容从右侧进入并向左滑动。
- 日期和曲线在同一个容器内同步过渡，时长约 `280ms`；系统要求减少动态效果时取消位移动画。
- 点击中间日期区域打开原生日期选择器，选中任意日期后跳到其所在的周一至周日。
- 当前周不能继续进入未来周；未来尚未采集的日期保持空白。
- 缺失数据为 `null`，折线在缺失处断开，不能补零或制作模拟数据；整周为空时保留日期和图表区域。

## 数据接口

新增当前会话私有接口：

```http
GET /api/me/accounts/{accountId}/daily-usage?start=2026-08-17&end=2026-08-23
```

接口行为：

- 必须存在有效 Cookie 会话，且账号必须属于该会话。
- `start` 和 `end` 必须是有效的 `YYYY-MM-DD` 日期，范围包含首尾两天。
- `start` 不得晚于 `end`，单次范围最多 `366` 天。
- 响应返回连续日期数组；没有快照或无法计算每日用量的日期仍返回对应日期，`used` 为 `null`。
- `complete` 和 `reset_adjusted` 且金额有效时返回数值；其他情况返回 `null` 并保留可用于界面状态的标准化状态。

示例：

```json
{
  "start": "2026-08-17",
  "end": "2026-08-23",
  "points": [
    { "date": "2026-08-17", "used": 12.5, "status": "complete" },
    { "date": "2026-08-18", "used": null, "status": "missing" }
  ]
}
```

`/api/me` 保持轻量，不内嵌整段历史。排行榜接口不增加每日字段。

## 页面结构

周趋势放在账号指标和进度条之后、账号操作之前：

1. 标题显示“周用量”，右侧显示本周有效数据合计；完全无数据时显示 `—`。
2. 日期导航由左箭头、三行日期按钮、右箭头组成；图标按钮使用 Lucide，并提供键盘焦点和无障碍名称。
3. 图表采用 Chart.js 单条平滑折线，带低透明度面积填充和点标记。纵轴单位为 USD 且从零开始，不显示多余图例。
4. 桌面悬停、移动端点按显示日期、星期、金额或“暂无数据”。
5. 图表容器固定高度，加载、空数据和错误状态不能改变卡片宽高。

颜色、边框、字号和亮暗模式继续使用现有 CSS 变量，不替换当前页面设计体系。移动端保持七列日期可读，账号卡片不产生横向滚动。

## 状态与并发

- 初次渲染账号卡片后，每个账号独立请求当前周七天数据。
- 同一账号同一周的响应保存在页面内存中，返回看过的周时直接复用；页面刷新后重新读取。
- 快速连续切周时使用请求序号忽略过期响应，避免较慢的旧请求覆盖新周。
- 单个账号加载失败只在自己的图表区域显示错误和重试按钮，不影响其他账号或 `/api/me` 的指标。
- 账号刷新会保留仍存在账号的所选周和已加载周数据；被解绑账号的图表实例和状态会清理。
- Chart.js 脚本不可用时保留日期导航并显示图表不可用状态。

## 测试与验收

- 接口测试覆盖连续七天填充、有效金额、缺失/失败状态、日期格式、反向范围、366 天上限、无会话和跨会话访问。
- 静态页面测试覆盖 Chart.js、日期三行结构、每账号图表容器、周切换、日期选择、方向动画和减少动态效果。
- 自动测试全部通过后，在本地使用真实页面做桌面与手机宽度检查。
- 浏览器验证亮暗主题、上一周/下一周、未来周禁用、日期跳转、空周、错误重试、键盘焦点和无横向滚动。
